# AI Agent Rules

This document explains why AI coding agents need explicit boundaries, and how RepoBlackbox's safety documents work together to enforce them.

---

## Why AI Coding Agents Need Boundaries

AI coding agents — Claude Code, Codex, Cursor, Copilot, and others — are powerful. They can write, refactor, and fix code faster than any developer working alone.

But they have a fundamental limitation: **they do not know what they are not supposed to touch.**

Unless told explicitly, an agent may:

- Edit `package.json` because it "needs" to add a dependency
- Modify `.env` example files because it is "trying to help"
- Refactor an auth module because it noticed "related code"
- Delete a feature it considers "redundant"
- Update a lock file as a side-effect of another change
- Change a config file to fix what it thinks is a misconfiguration

None of these are bugs in the agent. They are natural consequences of letting an agent operate without boundaries.

**RepoBlackbox enforces the boundary conversation before the agent starts.**

## The Four Safety Documents

`repoblackbox init` creates four documents that work together:

### 1. `AGENT_RULES.md`

General rules the agent must follow in every session. Paste this into every AI coding session alongside your task.

**Covers:**
- Read scope before editing
- Keep changes minimal
- Do not touch protected files
- After editing, list every changed file and why

**When to update:** When you learn a new pattern of agent misbehavior that isn't already covered.

### 2. `TASK_SCOPE.md`

Task-specific boundaries for the current session. Generated by `repoblackbox scope`. Overwritten each session.

**Covers:**
- What the task is
- Which files/patterns are allowed
- Which files/patterns are forbidden
- What success looks like
- Session-specific notes for the agent

**When to update:** Before every AI coding session. Run `repoblackbox scope` to regenerate.

### 3. `PROJECT_CONTEXT.md`

High-level description of the project. Paste into long sessions where the agent needs context.

**Covers:**
- Project name and purpose
- Framework and key libraries
- Key directory structure
- Anything the agent should know to avoid breaking things

**When to update:** When your stack changes significantly.

### 4. `PROTECTED_FILES.md`

A human-readable list of protected file patterns. The machine-readable version is `.repoblackbox/protected-files.json`.

**Covers:**
- Env / secrets
- Auth / billing / payments
- Deployment / CI files
- Database / migration files
- And the override procedure for when you intentionally need to touch one

**When to update:** When you add new protected areas to your project.

## How to Use These With Claude Code

### Minimal setup (every session)

```
Read AGENT_RULES.md and TASK_SCOPE.md before editing any code.
Only touch files listed in the Allowed section of TASK_SCOPE.md.
Do not touch files listed in the Forbidden section.
After finishing, list every file you changed and why.
```

Then paste the contents of `TASK_SCOPE.md` directly into the message.

### Full setup (first session or complex tasks)

Attach all four documents:
1. `AGENT_RULES.md`
2. `PROJECT_CONTEXT.md`
3. `TASK_SCOPE.md`
4. `PROTECTED_FILES.md`

Instruct the agent: *"Read all four files before starting. Follow the rules. Stay within scope."*

### Example message for Claude Code

```
Before you start, read these files:

--- AGENT_RULES.md ---
[paste content]

--- TASK_SCOPE.md ---
[paste content]

Now do the task described in TASK_SCOPE.md.
After finishing, list every file you changed and why.
```

---

## How to Use These With Cursor

Cursor's "Rules for AI" feature (`@rules`) can include `AGENT_RULES.md` permanently. Add it once and it applies to every session in the workspace.

Then paste `TASK_SCOPE.md` for each individual task.

---

## How to Use These With Codex / OpenAI APIs

Include `AGENT_RULES.md` as a system message. Pass `TASK_SCOPE.md` as user context before each coding request.

---

## After Every AI Session

```bash
repoblackbox audit
repoblackbox report
```

Review the report. If the agent violated scope — touch a forbidden file or modified something outside the allowed patterns — the audit will tell you exactly what happened.

The report is your flight log. Keep it.
